# Развёртывание

## Состав

- `pocketbase`: PocketBase, миграции и внутренний транзакционный обработчик.
- `mgkct`: Shelf API и статическая сборка Flutter Web.
- Том `mgkct_data`: данные PocketBase. Имя ключа тома сохранено.

Скопируйте бинарник PocketBase 0.40.1 для архитектуры хоста в
`data/pocketbase/pocketbase`. Dockerfile использует этот бинарник без скачивания.

## Контейнеры

Создайте `.env` по `.env.example`, задайте случайный пароль `PB_SERVICE_PASSWORD`.
Сервисный аккаунт нужен только серверу. Не используйте старые демонстрационные аккаунты
на рабочем сервере; удалите или смените их пароли через админку.

```bash
bash build.sh
```

Скрипт поддерживает Docker Compose и Podman. Клиент и сервер доступны на
`http://<сервер>:8090`, админка PocketBase — только локально на
`http://127.0.0.1:8091/_/`. Для доступа администратора с другой машины используйте
SSH-туннель; порт хранилища наружу не публикуйте. При необходимости поставьте перед
Shelf HTTPS-прокси. Сервисный пароль не должен попадать в параметры Flutter-сборки.

Для внутренних имён контейнеров и localhost в `NO_PROXY` и `no_proxy` добавлены
исключения. Это сохраняет внешний прокси для остальных адресов и позволяет Shelf
подключаться к PocketBase напрямую. Podman автоматически наследует прокси хоста;
без исключения для `pocketbase` внутренние запросы могут получать HTTP 503.
Изменения окружения требуют пересоздания контейнера, обычного `restart` недостаточно.

```bash
docker compose --env-file .env -f docker-compose.yml ps
docker compose --env-file .env -f docker-compose.yml logs mgkct
curl http://127.0.0.1:8090/api/health
```

`entrypoint.sh` применяет миграции и настраивает сервисный аккаунт из окружения.
Демонстрационные преподаватели и назначения автоматически не создаются. Добавьте
пользователей в `users` (email, пароль, `display_name`, `role`) и назначения
через закрытую админку PocketBase. Отдельная запись профиля не нужна.

## Обновление существующей установки

Перед обновлением остановите запись и старый сервер, сохраните копию **всего** `pb_data`.
Не копируйте работающую SQLite-базу обычным `cp`: остановите контейнер или используйте
штатный backup PocketBase.

Миграции применяются по порядку:

- `1756000000000_init_collections.js` — историческая схема.
- `1788048000000_english_names.js` — английские имена коллекций и полей.
- `1788134400000_monthly_reports.js` — заголовки отчётов, версии, связи,
  уникальные ограничения и закрытие прямого доступа обычным пользователям.
- `1788220800000_unified_users.js` — перенос ФИО и ролей в `users`, перевод
  ссылок на преподавателей и подтверждающих на `users`, удаление `user_profiles`.

Миграция месячных отчётов сохраняет существующие строки и замены. Если обнаружены дубликаты
назначений в одном месяце, смешанные статусы или несколько профилей одного аккаунта,
она завершается ошибкой и откатывает транзакцию. Такие данные нужно проверить на копии
базы и согласованно исправить до обновления; автоматического удаления или объединения нет.

Объединение пользователей сохраняет ID аккаунтов, email, хэши паролей, ключи токенов,
назначения, часы, статусы и историю подтверждений. Ссылки с ID профилей переводятся
на ID соответствующих аккаунтов. Поле `profileId` в JSON API оставлено для клиента,
но теперь равно `id` пользователя. После обновления перезагрузите приложение и войдите
заново, чтобы убрать из памяти старые ID профилей.

Перед объединением у каждого аккаунта `users` должен быть ровно один профиль.
Несовпадающие email или непустые ФИО, отсутствующие аккаунты/профили, повреждённые связи
и дополнительные поля профиля останавливают миграцию с ошибкой без частичного переноса.
Дополнительные множественные связи с профилями также требуют отдельной миграции.
Не исправляйте конфликты удалением записей: сначала проверьте их на копии базы.
Служебные суперпользователи `_superusers` объединением не затрагиваются.

Старый клиент с новой схемой несовместим: хранилище, Shelf и клиент обновляются вместе.
`build.sh` останавливает старый единый контейнер перед подключением его тома
к новому контейнеру PocketBase. Compose-файл находится в корне и явно сохраняет
прежнее имя проекта по умолчанию — `docker`, поэтому том остаётся `docker_mgkct_data`.
Если установка использовала другое имя проекта, задайте прежнее значение через
`COMPOSE_PROJECT_NAME` в `.env` или окружении; при ручном запуске допустим также `-p`.
Не выполняйте `down -v`. Не запускайте два PocketBase на одном томе.
Для Podman сохраняется фактическое имя `mgkct_data`; у Compose есть префикс проекта.

При ручном запуске укажите существующий `PB_DATA_DIR`. Для прежнего локального пути
`tools/pocketbase/pb_data` предусмотрено автоматическое обнаружение; файлы не перемещаются.
При смене машины копируйте базу явно, не полагайтесь на каталог по умолчанию.

Схемы месячных отчётов и объединённых пользователей не имеют автоматического обратного перехода. Откат выполняется
восстановлением полной резервной копии и предыдущих образов при остановленном сервере.
Записи, сделанные после резервного копирования, потребуют отдельного переноса.

## Без контейнеров

Запустите PocketBase скриптом `data/pocketbase/run.sh`, а Shelf — из `server/`.
Все пути конфигурации и секреты задаются окружением; пример есть в `.env.example`.
Соберите Flutter из `client/` и укажите абсолютный путь `STATIC_DIR` к `client/build/web`
при запуске Shelf. Клиент обращается к тому же origin по `/api`.

```bash
cd client
flutter pub get
flutter build web --release
```

```bash
cd server
dart pub get
mkdir -p build
dart compile exe bin/server.dart -o build/server
```

Перед запуском бинарника задайте `PB_SERVICE_EMAIL`, `PB_SERVICE_PASSWORD`,
`POCKETBASE_URL` и `STATIC_DIR`. Для доступности по сети задайте `HOST=0.0.0.0`.
Хранилище при этом должно слушать localhost либо находиться в закрытой сети.

## Резервные копии

Сохраняйте весь каталог данных PocketBase, конфигурацию окружения в защищённом месте
и версии обоих образов. Регулярно проверяйте восстановление на отдельной машине.
Секреты и рабочие базы исключены из Git и контекста Docker-сборки.
Бинарник PocketBase исключён из Git, но входит в образ хранилища.

## Нативные клиенты

Адрес Shelf задаётся `--dart-define=API_BASE_URL=https://<адрес-api>`.
Application/bundle ID после переименования проекта отличаются от старых; установка
с новым ID является отдельным приложением и требует повторного входа.
