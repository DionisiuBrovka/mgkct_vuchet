# Вычитка

Web-приложение учёта учебной нагрузки. Преподаватель заполняет месячный отчёт
и отправляет его; завуч проверяет, возвращает или подтверждает. Интерфейс
русский, технические имена английские.

## Состав

`client/` — Flutter Web; `server/` — Shelf API и правила; `data/pocketbase/`
— PB 0.40.1, схема и storage hooks. Браузер обращается только к Shelf: PocketBase
и service credentials ему недоступны.

Учебный год: сентябрь–июль; августа нет. Часы — точные decimal strings, а не
`double`. Статусы: `draft → submitted → confirmed`, возврат переводит
`submitted` обратно в `draft`; confirmed read-only. Сессия — HttpOnly cookie.

## Пользователи и данные

В закрытой PB admin UI создайте `users` с email, password, `name`, role
(`teacher` или `admin`), `is_active` и `auth_version`. Одинаковые ФИО допустимы:
на входе они различаются хвостом ID. Создайте subjects, groups и assignments;
`academic_year` — год начала учебного года. В назначении заполните
`planned_main_hours` (основные часы) и `planned_additional_hours` (допконтроль)
на учебный год: строки `120` или `12.5`, без запятой и лишних конечных нулей.
Пустое поле означает «план не задан», `0` — нулевой план. В карточках отчёта
обе роли видят годовые подтверждённые часы, часы на проверке и остаток.
Превышение подсвечивается, отправка разрешена. Не используйте рабочие учётные
записи в тестах.

## Проверка

```bash
bash scripts/check.sh
```

Скрипт не читает `.env` и использует временные данные. Он требует Dart, Flutter,
Python 3, `curl` и `unzip`. Закреплённый PocketBase 0.40.1 автоматически
скачивается в ignored `data/pocketbase/pocketbase` с проверкой SHA-256. CI
запускает ту же команду.

## Установка на чистый Debian 13 (без контейнеров)

Нужен Debian 13 **amd64/x86_64**, systemd, доступ в интернет и root/sudo.
Для сборки рекомендуются 4 ГБ RAM и минимум 10 ГБ свободного места плюс место
под данные и резервные копии. Скопируйте весь проект на сервер и из его корня
выполните одну команду:

```bash
sudo bash scripts/deploy.sh debian
```

Если `sudo` не установлен, войдите через `su -`, перейдите в каталог проекта
и выполните `bash scripts/deploy.sh debian`. Скрипт спросит адрес, по которому
пользователи будут открывать приложение, предложив IP сервера и порт 8090.
Адрес лучше закрепить в DHCP или настройках сервера. Без интерактивного ввода:

```bash
sudo bash scripts/deploy.sh debian --origin http://192.168.1.10:8090
```

Замените IP на адрес своего сервера. Разрешены HTTP, DNS-имя или IPv4 и порт
1024–65535, кроме 8091. Открывайте приложение именно по указанному адресу:
он используется для проверки Origin при входе и сохранении. Это установка
для доверенной локальной сети; публикация в интернете с HTTPS требует отдельной
настройки reverse proxy. Скрипт не меняет правила существующего firewall:
если входящие подключения закрыты, разрешите выбранный TCP-порт из своей LAN.

Скрипт устанавливает пакеты через APT, скачивает Flutter 3.44.8 (Dart 3.12.2)
и PocketBase 0.40.1 с проверкой SHA-256, собирает код отдельным системным
пользователем и запускает две службы systemd. Никакие Docker/Podman для этого
не требуются. Создаётся пустая рабочая база и пользователь приложения **Завуч**.
Тестовые преподаватели и отчёты не переносятся. После установки прочитайте пароли:

```bash
sudo cat /etc/mgkct/credentials.txt
```

Откройте показанный адрес, выберите «Завуч» и введите начальный пароль.
Преподавателей, предметы, группы и назначения добавьте через PocketBase.

### PocketBase на сервере

PocketBase слушает только `127.0.0.1:8091`. На своём компьютере откройте туннель:

```bash
ssh -N -L 18091:127.0.0.1:8091 user@192.168.1.10
```

Пока SSH работает, откройте [админку PocketBase](http://127.0.0.1:18091/_/).
Email и пароль указаны в `credentials.txt`; если локальный 18091 уже занят,
замените его в SSH-команде и адресе браузера. Учётная запись PocketBase служебная:
изменение её пароля требует согласованного обновления
`/etc/mgkct/install.json` и повторного запуска установщика. Пароль завуча можно
менять в коллекции `users`; установщик при обновлении его не сбрасывает.

### Обновление, службы и данные

Скопируйте свежий код и снова выполните `sudo bash scripts/deploy.sh debian`.
Сборка проходит до остановки служб. Затем скрипт останавливает приложение и PB,
сохраняет полную копию базы и конфигурации, применяет миграции, переключает
версию и проверяет готовность HTTP. Пароли и данные сохраняются. При ошибке
после остановки служб исправьте указанную причину и повторите команду;
неудачная миграция не вызывает автоматического удаления или отката данных.

```bash
sudo systemctl status mgkct-app mgkct-pocketbase
sudo journalctl -u mgkct-app -u mgkct-pocketbase -n 100
sudo systemctl restart mgkct-pocketbase mgkct-app
sudo systemctl stop mgkct-app mgkct-pocketbase
sudo systemctl start mgkct-pocketbase mgkct-app
```

Обе службы включены в автозапуск и работают под отдельными пользователями.
Сборочный пользователь не имеет доступа к базе и паролям.

| Что | Где |
|---|---|
| База и файлы PocketBase | `/var/lib/mgkct/pb_data` |
| Настройки и секреты (root, 0600) | `/etc/mgkct/` |
| Текущий выпуск и сохранённые версии | `/opt/mgkct/current`, `/opt/mgkct/releases/` |
| SDK и кэш сборки | `/var/cache/mgkct-build/` |
| Копии перед обновлением | `/var/backups/mgkct/<дата-время>/` |

Копия содержит `pb_data.tar`, `config/` и `release.txt` с путём предыдущей версии.
Для восстановления остановите обе службы, сохраните текущий каталог данных
под другим именем, распакуйте `pb_data.tar` в `/var/lib/mgkct`, восстановите
конфигурацию и ссылку `current` на версию из `release.txt`, затем запустите службы.
Восстанавливайте код и базу согласованно. Копии и старые версии не удаляются
автоматически; следите за местом и храните отдельную копию на другом устройстве.
Установщик не настраивает регулярное резервное копирование.

Файл `.env` из скопированного проекта в этом режиме не читается. При переносе
существующей базы без конфигурации установщик останавливается, чтобы не принять
её за новую. Автоматическая миграция старой версии схемы не предусмотрена.

## Deploy (Linux x86_64, Podman)


```bash
cp .env.example .env
# замените PB_SERVICE_PASSWORD и PUBLIC_ORIGIN
bash scripts/deploy.sh up
bash scripts/deploy.sh status
bash scripts/deploy.sh logs
```

`down` останавливает контейнеры, но не удаляет volume `mgkct_data`. PB публикуется
только на localhost; Shelf/Web — на `APP_BIND:APP_PORT`. Для публичной сети нужен
явно настроенный HTTPS reverse proxy. Проверка без рабочей `.env`:

```bash
bash scripts/deploy.sh --self-test
```

Для локального PB без контейнеров обязательно задайте абсолютный `PB_DATA_DIR`;
скрипты не выбирают и не мигрируют старые базы автоматически.

## Статистика завуча

В кабинете завуча откройте «Годовая статистика и Excel». Выберите учебный год
или все годы, при необходимости преподавателя, предмет и группу. Предпросмотр
показывает план, подтверждённые часы, часы на проверке и остаток отдельно для
основных часов и допконтроля. Кнопка «Скачать Excel» создаёт `.xlsx` по тем же
фильтрам. Черновики и замены в выполнение планов не входят. Длинные дробные
значения в Excel записываются текстом без потери точности.

## Ограничения

Нет печати, комментариев, массового подтверждения, клиентского администрирования
и офлайн-синхронизации. Полные контракты и QA-протоколы находятся в `task/`.
