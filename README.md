# Вычитка — учёт учебной нагрузки преподавателей

Приложение для ежемесячного учёта проведённых занятий и замен в колледже.
Преподаватель заполняет отчёт, отправляет его завучу, завуч подтверждает или
возвращает отчёт на доработку. Интерфейс — на русском, технические имена — на английском.

## Архитектура

```text
Браузер / нативный Flutter-клиент
                ↓ HTTP / JSON
          Dart Shelf API
                ↓ внутренний API
      PocketBase / SQLite
```

| Каталог | Ответственность |
|---|---|
| `client/` | Flutter: экраны, формы, отображение статусов, локальное состояние ввода |
| `server/` | Dart Shelf: авторизация, права доступа, валидация, отчёты и итоги |
| `data/pocketbase/` | Миграции, ограничения схемы, транзакционное хранилище, запуск PocketBase |
| Корень: `Dockerfile`, `pocketbase.Dockerfile`, `docker-compose.yml`, `build.sh`, `entrypoint.sh` | Отдельные образы и запуск сервера с клиентом и хранилища |

Клиент не использует PocketBase SDK и не знает имён его коллекций и полей.
Все операции выполняются через Shelf API. На клиенте остаются предварительная
проверка формы и вычисления для отображения; окончательную проверку делает сервер.

## Технологии

- Клиент: Flutter, Cubit / flutter_bloc, Freezed, go_router, get_it, HTTP.
- Сервер: Dart, Shelf, shelf_router, shelf_static, PocketBase SDK.
- Данные: PocketBase 0.40.1, SQLite, миграции и внутренний транзакционный обработчик.
- Развёртывание: два контейнера; Shelf раздаёт также собранный Flutter Web.

## Интерфейс

AppBar использует основной синий цвет приложения. На экранах входа, выбора месяца,
заполнения и проверки отчёта есть пояснения следующих действий. Подсказки учитывают
статус отчёта; сокращения видов часов можно раскрыть в форме, а статусы и значки
снабжены всплывающими пояснениями. На узких экранах поля часов расположены в два ряда.
На экране проверки назначения представлены карточками с предметом, группой,
полными названиями видов нагрузки и итогом; нулевые значения показаны приглушённо.
Итоги по назначениям отделены от часов замен.

## Пользователи и права

Вход выполняется выбором пользователя и вводом пароля. Список входа содержит только
ID и ФИО; email и роли публично не выдаются. Одинаковые ФИО различаются по ID.

| Операция | Преподаватель | Завуч |
|---|---|---|
| Просмотр отчётов | Только своих | Всех преподавателей |
| Изменение часов и замен | Свой черновик | Нет |
| Отправка | Свой черновик | Нет |
| Подтверждение / возврат | Нет | Только отчёт на проверке |
| Изменение подтверждённого отчёта | Нет | Нет |

Shelf проверяет токен через PocketBase и читает актуальную роль из учётной записи `users`.
Контекст пользователя не разделяется между запросами. Сервисный аккаунт PocketBase
используется только сервером; его пароль и токен не передаются клиенту.

Прямое чтение и изменение прикладных коллекций обычными пользователями закрыто
правилами PocketBase. Администрирование аккаунтов и назначений выполняется через
закрытую админку PocketBase. Автоматического создания демонстрационных пользователей нет.

Для добавления преподавателя достаточно одной записи в `users`: заполните `email`,
пароль и его подтверждение, `display_name` (ФИО), `role` (`teacher` — преподаватель,
`admin` — завуч). Отдельный профиль создавать не нужно. Встроенное необязательное
поле `name` приложение не использует — повторять в нём ФИО не требуется.
В `assignments.teacher` выбирается эта же запись `users`.

## Месячный отчёт

Отчёт определяется ID преподавателя, месяцем и календарным годом.
Учебный год длится с сентября по июль. Сервер учитывает точную принадлежность месяца
учебному году при формировании статусов.

```text
draft → submitted → confirmed
           ↓
         draft
```

- Черновик содержит назначения преподавателя и список замен.
- Часы и замены редактируются локально и сохраняются вместе кнопкой сохранения
  или отправки. Удаление замены затрагивает только выбранный ID.
- Сервер проверяет диапазон часов 0–999, принадлежность назначений, календарную дату
  замены и её соответствие месяцу. Лабораторные и практические часы объединены.
- Отчёт только с заменами допустим. Полностью пустой отчёт отправить нельзя.
- Статус хранится у отчёта, а не вычисляется по наиболее продвинутой строке.
- Каждое сохранение содержит `revision`. Устаревшая версия получает HTTP 409.
- Отчёт, его строки и замены записываются одной транзакцией PocketBase.
  Внутренний обработчик проверяет версию и сохраняет данные; права и бизнес-правила
  реализованы в Dart на Shelf.
- При ошибке сети, валидации или конфликте сохранения данные остаются в форме.
  Истечение сессии требует повторного входа. После конфликта версий
  нужно заново открыть актуальный отчёт; автоматического слияния изменений нет.
- Подтверждённые отчёты доступны завучу для просмотра, включая часы по каждому виду
  нагрузки в каждом назначении.

## Данные

| Коллекция | Содержимое |
|---|---|
| `users` | Учётные записи PocketBase: email, хэши паролей, ФИО (`display_name`) и роль |
| `assignments` | Преподаватель, предмет, группа, год начала учебного года |
| `teaching_reports` | Период, преподаватель, статус, версия и сведения о подтверждении |
| `teaching_report_entries` | Строки отчёта, связь с назначением, шесть видов часов |
| `substitutions` | Замены с собственным ID и связью с отчётом |

Уникальны пары «отчёт + назначение» и периоды «преподаватель + месяц + год».
Исторические поля статуса у строк сохранены для совместимости данных и обновляются
вместе с заголовком отчёта. Источник статуса для API — `teaching_reports`.

| Dart / API | PocketBase | Значение |
|---|---|---|
| `lectureHours` | `lecture_hours` | Лекции |
| `practicalHours` | `practical_hours` | Лабораторные и практические занятия |
| `courseProjectHours` | `course_project_hours` | Курсовые проекты |
| `consultationHours` | `consultation_hours` | Консультации |
| `additionalAssessmentHours` | `additional_assessment_hours` | Дополнительный контроль |
| `examHours` | `exam_hours` | Экзамены и дифференцированные зачёты |

ФИО, группы, предметы и названия месяцев остаются пользовательскими данными на русском.

## HTTP API

Все маршруты начинаются с `/api`. За исключением списка входа, входа и health-check,
требуется заголовок `Authorization: Bearer <token>`.

| Метод и маршрут | Назначение |
|---|---|
| `GET /health` | Доступность API и хранилища |
| `GET /auth/users` | Список ID и ФИО для входа |
| `POST /auth/login` | Вход: `profileId` (ID записи `users`), `password`; ответ: `token`, `user` |
| `GET /auth/me` | Текущий пользователь |
| `GET /teachers/:id/years/:year` | Статусы месяцев учебного года |
| `GET /admin/months/:year/:month` | Преподаватели и статусы за месяц |
| `GET /reports/:teacher/:year/:month` | Отчёт со строками, заменами, итогами и версией |
| `POST /reports/:teacher/:year/:month/save` | Сохранение всего черновика |
| `POST /reports/:teacher/:year/:month/submit` | Сохранение и отправка одной операцией |
| `POST /reports/:teacher/:year/:month/confirm` | Подтверждение завучем |
| `POST /reports/:teacher/:year/:month/reject` | Возврат в черновик |

Для сохранения/отправки передаются `revision`, `entries`, `substitutions`.
Для подтверждения/возврата — только `revision`; автора и время устанавливает сервер.
Ошибки возвращаются как JSON с полем `message`: 401 — вход, 403 — права,
409 — конфликт версии/статуса, 422 — некорректные данные.

## Локальный запуск

Требуются Flutter, Dart SDK 3.10+ и бинарник PocketBase 0.40.1 в
`data/pocketbase/pocketbase` (не хранится в Git).

Скопируйте `.env.example` в `.env`, замените пароль сервисного аккаунта на случайный
и загрузите окружение в каждой серверной консоли:

```bash
set -a
source .env
set +a
```

Первичная настройка сервисного аккаунта при остановленном PocketBase:

```bash
bash data/pocketbase/bootstrap.sh
```

Хранилище и сервер запускаются в разных терминалах:

```bash
bash data/pocketbase/run.sh
```

```bash
cd server
dart pub get
dart run bin/server.dart
```

Для Flutter Web на отдельном порту (origin уже указан в `.env.example`):

```bash
cd client
flutter pub get
flutter run -d chrome --web-port=3000 --dart-define=API_BASE_URL=http://127.0.0.1:8080
```

В release-сборке Web адрес API по умолчанию совпадает с адресом страницы.
Для нативного клиента адрес задаётся `API_BASE_URL` при сборке; локальный default —
`http://127.0.0.1:8080`. При размещении на другой машине укажите адрес Shelf, не PocketBase.

`PB_DATA_DIR` задаёт каталог базы. Если в рабочем каталоге сохранилась прежняя база
`tools/pocketbase/pb_data`, скрипты используют её; иначе — `data/pocketbase/pb_data`.
Рабочие данные не перемещаются автоматически. Запуск скриптов применяет миграции.

## Проверки

```bash
python3 -m unittest discover -s data/pocketbase/tests -v
```

```bash
cd server
dart test
dart analyze
mkdir -p build
dart compile exe bin/server.dart -o build/server
```

```bash
cd client
flutter test
flutter analyze
flutter build web --release
```

Серверные тесты запускают отдельные экземпляры Shelf и PocketBase на localhost,
проверяют роли, блокировку прямого доступа, сохранение, статусы, валидацию,
конкурентные запросы и учебный год. Клиентские тесты проверяют сохранность ввода
при ошибке, единый запрос отправки и просмотр подтверждённого отчёта.
Миграционные тесты используют временные базы.

## Эксплуатация и ограничения

[DEPLOY.md](DEPLOY.md) описывает контейнеры, обновление схемы и резервные копии.
PocketBase доступен только серверу и администратору. Для удалённого доступа к Shelf
нужен HTTPS на обратном прокси. CORS задаётся явным списком `ALLOWED_ORIGINS`.
Лимит входа — 20 попыток в минуту на адрес соединения в пределах одного процесса.

Сессия клиента хранится в памяти; после перезапуска требуется вход. Офлайн-синхронизации,
экспорта и интерфейса управления назначениями нет. Сервисный аккаунт имеет права
суперпользователя PocketBase и должен оставаться изолированным от клиентских устройств.
