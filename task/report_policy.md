# Политика периода и неизменности отчёта

Статус: нормативное решение Task 03 от 2026-09-17. Основано на ответе
владельца «Принимаю все рекомендации» от 2026-09-17, зафиксированном в
[open_questions.md](open_questions.md). При конфликте приоритет имеет
[product_spec.md](product_spec.md), затем этот документ.

## Термины и источник времени

- **Календарный период отчёта** — русское имя месяца из списка ниже и его
  календарный год. Уникальность отчёта: teacher + month + calendar year.
- **Учебный год N/N+1** — с сентября календарного года N до июля N+1,
  включительно; в нём ровно 11 отчётных месяцев.
- **Текущий учебный год** и доступ преподавателя определяет Shelf по времени
  сервера в зоне `Europe/Minsk`. Клиентские часы не используются как источник
  права или периода. Runtime Task 08 фиксирует, что контейнер/host передаёт
  корректное время; тесты вводят time source, а не зависят от реальных часов.
- **Август** не является отчётным месяцем. Он принадлежит завершившемуся
  учебному году только для выбора текущего набора месяцев; отдельный августовский
  отчёт создать или открыть нельзя.

| Месяц отчёта | Календарный год для учебного N/N+1 |
|---|---|
| Сентябрь, Октябрь, Ноябрь, Декабрь | N |
| Январь, Февраль, Март, Апрель, Май, Июнь, Июль | N + 1 |

### Границы дат

| Серверная дата в Europe/Minsk | Текущий учебный год | Что видит и может открыть teacher | Администратор |
|---|---|---|---|
| 31 декабря 2026 | 2026/2027 | Сентябрь–декабрь 2026 и январь–июль 2027 | Может выбрать любой существующий прошлый период и текущий 2026/2027 |
| 1 января 2027 | 2026/2027 | тот же набор 11 месяцев | тот же доступ; смена календарного года не меняет учебный год |
| 31 июля 2027 | 2026/2027 | тот же набор, включая июль 2027 | тот же доступ |
| 1 августа 2027 | 2026/2027 | тот же завершившийся набор; августа нет | может просматривать прошлые периоды и 2026/2027 |
| 31 августа 2027 | 2026/2027 | тот же завершившийся набор; августа нет | тот же доступ |
| 1 сентября 2027 | 2027/2028 | Сентябрь–декабрь 2027 и январь–июль 2028 | текущий и существующие прошлые периоды |

Учитель не выбирает учебный год вручную. API period list возвращает серверно
вычисленный текущий учебный год, его 11 месяцев и статусы; клиент только
отображает результат. После смены 31 августа → 1 сентября старая teacher URL
или API-запрос периода предыдущего года отклоняется как недоступный учителю
(семантика статуса/error code закрепляется Task 06), а UI возвращает к
актуальному списку с сообщением. Это не удаляет старый отчёт и не ограничивает
администратора.

Завуч выбирает учебный год и месяц для просмотра. Ему доступны текущий год и
любые прошлые периоды с существующими отчётами; API не должен стирать или
скрывать такой отчёт при смене года. Future или несуществующий календарный
месяц, включая август, не является валидным period endpoint. Точные DTO списка
доступных административных периодов определяет Task 06; UI не вычисляет право
доступа по своему календарю.

## Жизненный цикл и права

Единственный источник статуса — `teaching_reports.status`. Клиент может
скрывать недоступное действие, но Shelf на каждой команде заново проверяет
сессию, роль, owner, текущий status и revision.

| Действие | Teacher | Admin | Предусловие и результат |
|---|---|---|---|
| читать свой текущий отчёт/месяцы | да | — | период в серверном текущем учебном году |
| читать любой отчёт | только свой текущий | да | admin может читать submitted и confirmed; доступ к draft в рамках review API определяется Task 06, но не даёт правки |
| сохранить draft | только свой | нет | status `draft`, точная валидность значений, актуальная revision; нулевой draft допустим |
| отправить | только свой | нет | status `draft`, актуальная revision, `grandTotal > 0`; атомарно `draft → submitted` |
| подтвердить | нет | да | status `submitted`, актуальная revision; атомарно `submitted → confirmed` |
| вернуть в черновик | нет | да | status `submitted`, актуальная revision; атомарно `submitted → draft` |
| редактировать confirmed | нет | нет | всегда отказ; статус не меняется |

Никаких иных переходов нет. `confirmed` нельзя вернуть, переписать или
подтвердить повторно. Любой conflict revision либо неподходящий status — 409;
окончательный код/JSON определит Task 06. Хранилище выполняет CAS, но не
заменяет server authorization и policy.

## Пустой, нулевой и отчёт с заменами

Значения часов — exact decimal strings из
[decimal_contract.md](decimal_contract.md). После server validation вычисляется
`grandTotal = assignmentTotal + substitutionTotal`.

| Состояние | Save draft | Submit | Причина |
|---|---|---|---|
| Нет строк/замен или все значения нулевые | да | нет, 422 | это полностью пустой отчёт |
| Есть положительная нагрузка по назначению | да | да | `grandTotal > 0` |
| Нет назначений, есть замена с положительными часами | да | да | отчёт только с заменами допустим |
| Нулевая замена среди других положительных строк | да | да, если дата и описание валидны | владелец принял рекомендацию разрешить её; она не меняет итог |
| Только нулевые замены | да | нет, 422 | `grandTotal = 0` |
| Неполная или невалидная decimal строка | нет как числовая команда | нет, 422 | raw UI-ввод сохраняется только локально до исправления |

Нулевая строка назначения не является сама по себе ошибкой; она учитывается
как `"0"`. Проверяется итог, а не наличие автоматически добавленных строк.
Сохранение draft не обходится без полной структурной проверки (принадлежность
строк, корректность даты и описания замены), но допускает `grandTotal = 0`.
При сетевой ошибке, 422 или 409 raw input остаётся в клиентской форме.

## Справочники и назначения

Владелец выбрал неизменяемость вместо snapshot-версий. Новая версия не хранит
историю и не добавляет версии справочников: связанная запись сохраняет свой
исходный смысл потому, что используемые справочник и назначение нельзя изменить
или удалить.

**Используемой** считается запись, на которую ссылается хотя бы одна строка
`teaching_report_entries`, независимо от статуса её отчёта (`draft`,
`submitted`, `confirmed`). Это защищает даже уже созданный draft от тихой
подмены предмета или группы.

| Объект | Пока не используется | После использования строкой отчёта |
|---|---|---|
| Subject | можно переименовать или удалить при отсутствии иных ссылок | нельзя переименовать или удалить |
| Group | можно переименовать или удалить при отсутствии иных ссылок | нельзя переименовать или удалить |
| Assignment: teacher, subject, group, academic year и иной смысловой атрибут | можно исправить или удалить при выполнении ограничений схемы | нельзя изменить или удалить |

Если требуется исправить использованный subject, group или assignment,
администратор создаёт новую запись/новое назначение и прекращает использовать
старое в новых отчётах. Старый отчёт сохраняет связи и отображаемые названия,
потому что исходные records неизменны. Это относится к действиям в закрытой
PB-админке так же, как к будущим внутренним операциям: Task 05/09 реализуют
ограничения ссылочной целостности и, при необходимости, PB hooks, а не полагаются
на дисциплину оператора.

### Состав draft при изменении назначений

Новая, ещё неиспользуемая assignment может появиться в текущем учебном году.
При явной повторной загрузке draft Shelf строит его состав из актуальных
назначений и добавляет строку с нулевыми значениями. При save/submit сервис
сверяет набор assignment IDs из свежего состояния с набором, который видел
клиент. Если состав изменился между read и command, команда получает 409 и
пользователь перезагружает отчёт; сервер не добавляет и не удаляет строки
молча. Удаление используемой assignment запрещено, а удаление неиспользуемой
также меняет состав и действует по тому же правилу reread.

Таким образом confirmed отчёт не меняется от позднего редактирования
справочника, submitted/draft не получают незаметную подмену, а новые назначения
не требуют истории версий или ручного выбора учебного года преподавателем.
