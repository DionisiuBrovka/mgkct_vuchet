# Runtime и развёртывание

Актуальный путь развёртывания — `sudo bash scripts/deploy.sh` на Debian 13
amd64 с systemd. Контейнерный деплой не поддерживается. `Dockerfile` оставлен
как отдельный рецепт сборки образа и не используется установщиком.

## Версии и источники

| Компонент | Версия | Источник |
|---|---|---|
| Flutter / Dart | 3.44.8 / 3.12.2 | архив Flutter из `storage.googleapis.com`, проверка SHA-256 в `deploy.sh` и `Dockerfile` |
| PocketBase | 0.40.1 | релиз GitHub, SHA-256 в `scripts/fetch-pocketbase.sh` |
| Сборочный образ Dart | 3.12.2-sdk | `docker.io/library/dart` в `Dockerfile` |

Установщик ставит системные зависимости через APT, скачивает закреплённые
артефакты, собирает Flutter Web и Shelf отдельным пользователем и запускает
`mgkct-app` и `mgkct-pocketbase`. Shelf раздаёт Web и API на выбранном LAN
адресе. PocketBase доступен администратору по IP сервера на порту 8091;
Shelf обращается к нему через `127.0.0.1:8091`.

## Конфигурация и секреты

На первой установке адрес берётся из `--origin`, затем из `PUBLIC_ORIGIN` в
корневом `.env`. Если оба отсутствуют, скрипт запрашивает адрес. `.env.example`
показывает формат. Переменные из `.env` читаются как данные, без выполнения
shell-кода. `--origin` имеет приоритет. На повторном запуске настройки из
`/etc/mgkct/install.env` сохраняются; явный `--origin` может изменить хост,
но не порт приложения.

При первой установке создаются разные случайные пароли по 8 буквенно-цифровых
символов для завуча и сервисной учётной записи PocketBase. Установщик хранит их
в `/etc/mgkct/install.env` и выдаёт человеку в `/etc/mgkct/credentials.txt`.
`app.env` генерируется для systemd. Все три файла имеют права 0600 и лежат
в каталоге root с правами 0700. Установщик не печатает пароли. При обновлении
пароли не меняются. Старый `install.json` переносится с сохранением значений.
Пароль завуча, изменённый вручную в PocketBase, установщик не сбрасывает.

## Данные и обновление

Данные лежат в `/var/lib/mgkct/pb_data`, релизы — в `/opt/mgkct/releases`,
SDK и сборочный кэш — в `/var/cache/mgkct-build`. Перед миграциями скрипт
останавливает службы и сохраняет базу и конфигурацию в `/var/backups/mgkct`.
Обычный деплой не удаляет данные. После переключения релиза скрипт ожидает
health PocketBase и Shelf. При ошибке выводит диагностику и ненулевой код;
автоматического отката миграций нет.

Локальная и CI-проверка: `bash scripts/check.sh`. Она использует временные базы,
не читает рабочий `.env` и не запускает установщик на машине разработки.
