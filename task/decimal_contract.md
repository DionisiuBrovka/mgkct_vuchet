# Контракт точных десятичных часов

Статус: нормативное решение Task 02 от 2026-09-17. Этот документ определяет
одно представление часов для новой версии. Он обязателен для Task 05 (схема),
06 (DTO), 09–14 (реализация), 17–18 (ввод). При конфликте приоритет имеет
[product_spec.md](product_spec.md), затем этот документ.

## Решение

Час — не JSON number и не `double`/`num`/JavaScript `Number`. Внешнее и
хранимое значение — каноническая ASCII-строка неотрицательного десятичного
числа. В Shelf и предварительном расчёте клиента оно разбирается в точный
value object:

```text
Decimal = { coefficient: BigInt >= 0, scale: int >= 0 }
value = coefficient × 10^(-scale)
```

`BigInt` и строковая десятичная запись сохраняют как длинную дробь, так и
целое больше `2^53 - 1`. `scale` не является заданной предметной точностью:
он выводится из принятой строки. При сериализации value object всегда
получается каноническая строка из раздела «Нормализация».

PocketBase хранит каждое поле часов как `TextField` с канонической строкой;
SQLite не получает `REAL`, а PB hook только переносит уже проверенные строки
внутри транзакции. В hook запрещены `Number`, `parseFloat`, арифметика и
форматирование часов. Task 05 задаёт конкретные TextField validation rules, а
Task 10 сохраняет их без преобразования.

## Границы и типы

| Граница | Принимает | Передаёт/хранит | Запрещено |
|---|---|---|---|
| Поле Flutter | сырая пользовательская строка | нормализованную decimal string только после завершённого разбора | `double.parse`, `num.parse`, округление, преобразование запятой в display-значении до завершения ввода |
| Flutter ↔ Shelf JSON | JSON string для каждого часа | каноническая decimal string | JSON number, `null`, bool, `NaN`, `Infinity` |
| Shelf application service | decimal string → `Decimal(BigInt, scale)` | результаты как decimal strings | binary float и неявный предел 999 |
| Shelf ↔ PB adapter/hook | внутренние канонические strings | TextField strings | `NumberField`, SQLite REAL, JS number arithmetic |
| Ответ Shelf ↔ UI | канонические decimal strings | UI-formatting из той же строки | ограничение числа дробных знаков или локальное пересчитывание как окончательного |

Преобразование UI → JSON → PB → JSON → UI поэтому не проходит через бинарную
плавающую точку. Временная UI-строка не обязана быть канонической и не хранится
как числовое значение до завершённого разбора.

## Ввод и нормализация

### Сырой ввод

Перед разбором удаляются только пробельные символы с начала и конца. Пробел,
неразрывный пробел, апостроф или иной символ внутри значения недопустимы; они
не являются разделителями тысяч. Десятичным разделителем во вводе может быть
одна ASCII-точка `.` или одна запятая `,`. Знак `+` или `-` не допускается,
включая `-0`.

Завершённый ввод имеет грамматику:

```text
completed = digits | digits? separator digits
digits    = [0-9]+
separator = "." | ","
```

Таким образом допустимы `1`, `1,25`, `1.25` и `,5`; для последнего
подразумевается нулевая целая часть. Недопустимы `.` и пустая дробная часть.
ASCII-цифры намеренны: арабские/локализованные цифры не имеют неявного
преобразования и получают ошибку, а интерфейс показывает понятную подсказку.

Пустое поле имеет особый завершённый смысл **ноль**. Это не то же самое, что
черновая незавершённая строка. В редакторе можно временно оставить `,`, `1,`
или `1.` при наборе: такие значения помечаются как incomplete, не участвуют в
предпросмотре как число и никогда не отправляются как decimal. При save/submit
клиент сохраняет raw text в форме, но не подменяет его нулём; действие должно
быть остановлено локально либо получить окончательный HTTP 422, если неполное
значение всё же попало в запрос.

### Нормализация завершённого значения

1. Пустой после trim ввод становится `"0"`.
2. Запятая заменяется точкой; при `,5` добавляется целая часть `0`.
3. Ведущие нули целой части удаляются, но целая часть никогда не исчезает.
4. Концевые нули дробной части удаляются; пустая дробная часть и точка
   удаляются.
5. Если коэффициент равен нулю, результат всегда `"0"`.

Каноническая грамматика результата:

```text
canonical = "0" | [1-9][0-9]*("."[0-9]*[1-9])?
```

Примеры: `000` → `"0"`, `0001,2500` → `"1.25"`, `,500` → `"0.5"`,
`1000.125` → `"1000.125"`. Канонизация изменяет только представление, не
значение. При показе UI может заменить точку на русскую запятую и показать
`1,5`; он не обязан сохранять введённое оформление `1,50` после успешного
round-trip. Никакое форматирование не добавляет и не отбрасывает значимые
цифры.

### Ошибки и предел размера

Экспонента (`1e3`, `1E-3`), смешанные разделители (`1,2.3`), несколько
разделителей, разделители тысяч (`1 000`, `1 000`, `1'000`, `1,000.25`), знак,
буквы, `NaN`, `Infinity`, JSON number и `null` — окончательная ошибка **422**.
Task 06 определит общий JSON envelope и машинный code этой ошибки; смысл ошибки
фиксирован как «некорректное десятичное значение часов».

Предметного максимума целой части, масштаба или количества слагаемых нет;
в частности, старый предел `999` отменён. Единственное техническое ограничение
— максимальный размер всего JSON body **1 048 576 байт UTF-8**, уже применяемый
нынешней HTTP-границей. Более крупный body отклоняется **413** до разбора и
никогда не обрезается. Это транспортный предел всего запроса, а не округление
или скрытый лимит дробных знаков; Task 06 обязан сохранить это значение либо
явно обновить одновременно API-contract и тесты.

## Точная арифметика

Разбор канонической строки удаляет точку, создаёт `BigInt coefficient` и
запоминает число дробных цифр как scale. Addition выравнивает меньший scale
умножением его coefficient на точную степень десяти и складывает `BigInt`.
После каждой публичной операции удаляются только незначащие конечные нули.
Вычитание, деление, округление, scientific notation и преобразование в
плавающую точку не нужны для этой версии.

Шесть полей записи часов имеют одинаковый тип `Decimal`:

| API field | Русская подпись |
|---|---|
| `lectureHours` | Лекции |
| `practicalHours` | Лабораторные и практические занятия |
| `courseProjectHours` | Курсовые проекты |
| `consultationHours` | Консультации |
| `additionalAssessmentHours` | Дополнительный контроль |
| `examHours` | Экзамены и дифференцированные зачёты |

Для отчёта Shelf вычисляет, не принимает от клиента и возвращает как
канонические strings:

```text
entryTotal(entry)       = sum(entry.sixHourFields)
fieldTotal(field)       = sum(entry[field] for every entry)
assignmentTotal         = sum(entryTotal for every entry)
substitutionTotal       = sum(substitution.hours for every substitution)
grandTotal              = assignmentTotal + substitutionTotal
```

`assignmentTotal` — итог часов по назначениям, не количество назначений.
Ноль — нейтральный элемент суммы. Предпросмотр клиента использует тот же
алгоритм, но ответ Shelf после read/save/submit/confirm/return является
окончательным. PB не хранит авторитетные итоги, если Task 05 не обоснует
отдельное производное поле; в любом случае оно не заменяет пересчёт сервисом.

## Нормативные примеры

| Сценарий | Ввод/операция | Ожидаемый результат |
|---|---|---|
| пустое поле | `"   "` | `"0"` |
| русская запятая и нули | `" 0001,2500 "` | `"1.25"` |
| короткие дроби | `"0.1" + "0.2"` | `"0.3"`, не `"0.30000000000000004"` |
| разделитель без целой части | `",5"` | `"0.5"` |
| большое допустимое значение | `"1000,125"` | `"1000.125"` |
| длинная дробь | `"0.123456789012345678901234567890123456789"` | тот же exact canonical string |
| сложение длинной дроби | предыдущее + `"0.000000000000000000000000000000000001"` | `"0.123456789012345678901234567890123457789"` |
| больше точного JS Number | `"9007199254740993" + "1"` | `"9007199254740994"` |
| все поля записи | `0.1`, `0.2`, `1.25`, `0`, `0`, `0` | `entryTotal = "1.55"` |
| отчёт | `assignmentTotal = "1.55"`, `substitutionTotal = "1000.125"` | `grandTotal = "1001.675"` |
| незавершённый raw text | `"1,"` | локально incomplete; не JSON decimal; save/submit не проходит до исправления |
| смешанные разделители | `"1,2.3"` | HTTP 422 |
| знак/экспонента | `"-0"`, `"1e3"` | HTTP 422 |
| JSON number | `0.1` вместо `"0.1"` | HTTP 422 |
| body больше 1 048 576 байт | любой JSON | HTTP 413, без усечения |

- Task 07: contract/unit/integration tests покрывают все строки из таблицы,
  round-trip через временный PB и отсутствие `double`/JS number на траектории.

## Проверка решения

Ручная сверка от 2026-09-17 выполнена методом точной коэффициентной арифметики:
`1 × 10^-1 + 2 × 10^-1 = 3 × 10^-1`; выравнивание 39-значной дроби с
`10^-36` даёт указанную строку без округления; `9007199254740993 + 1` остаётся
точным как `BigInt`. Сопоставление с текущим кодом подтвердило, что
`hours_input_field.dart` и report models используют `double`, сервис складывает
`num`, а PB миграции используют NumberField — все эти места должны быть
заменены только последующими задачами. Исходный код в Task 02 не изменяется.
