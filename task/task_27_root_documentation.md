## Цель

Свести актуальные пользовательские и инженерные инструкции к двум корневым документам, проверенным по реальному запуску.

## Ожидаемый результат

Переписанный README.md, новый AGENTS.md, удалённые после переноса DEPLOY.md/CLAUDE.md и исправленные ссылки.

## Объём работ

1. README описывает продукт/роли, архитектуру, точный стек, конфигурацию, локальный запуск, check, deployment, первый/повторный запуск, остановку/логи и типичные ошибки.
2. Документировать создание users/name/role/activity, subjects/groups/assignments в закрытой PB-админке, точные часы, учебный год/август, сессии и ограничения продукта.
3. Перенести полезные сведения о NO_PROXY, LAN, закрытом PB и секретах из старых документов; удалить устаревшие указания display_name/999/profileId/legacy transfer, не описывать отсутствующую native-поддержку.
4. Создать короткий AGENTS с картой, командами, правилами схемы/API/границ, изолированных тестов и содержательных комментариев. Различить завершённый чистый переход и будущие миграции уже новой версии.
5. Ссылаться на нормативные проектные документы task при необходимости, но устойчивые эксплуатационные сведения оставить в README/AGENTS; task — временный рабочий комплект. Исправить упоминание фактического main_task.md вместо несуществующего main_tasks.md в создаваемых документах.
6. После переноса удалить DEPLOY.md/CLAUDE.md и поправить ссылки. README описывает работающий продукт, не дорожную карту.
7. Проверить команды настройки на чистом окружении; отсутствие инструмента/сети описать точно, не объявлять непроверенный сценарий рабочим.

## Что не входит в задачу

План задач в корневом README, выдуманные фичи, расширение продукта, правка исходных обязательных источников task.

Общие исключения продукта: комментарии/история, экспорт/печать, массовое подтверждение, клиентская админка и офлайн-синхронизация.

## Затрагиваемые компоненты и файлы

- `README.md` — переписать.
- `AGENTS.md` — создать.
- `DEPLOY.md`, `CLAUDE.md` — удалить только после переноса.
- Ссылки в репозитории и `task/README.md` — актуализировать.

Пути исходного аудита могут уточняться по результатам зависимостей. Новый путь не считать существующим до проверки; расширение объёма обосновать.

## Функциональные требования

- В корне остаются README.md и AGENTS.md как основная Markdown-документация; полезные инструкции из старых файлов сохранены.
- Новый участник по README создаёт пользователей и назначения с одним name, запускает check и deploy без неописанных ручных действий.

Обязательные подробности поведения перечислены в объёме работ. Поля и DTO брать из зафиксированных контрактов.

## Архитектурные ограничения

- Сохранять согласованность с результатами зависимостей и приоритетом product_spec.
- Не добавлять совместимость со старой базой/API и функции вне §20.
- Добавлять содержательные комментарии только к неочевидной логике.
- Не раскрывать секреты и не удалять данные неявно; тестовый reset ограничен собственными ресурсами.
- Web — основная платформа; не изобретать удалённый CD или неизвестную инфраструктуру.

## Порядок выполнения

1. Проверить условия начала, результаты зависимостей и фактический код/документы из доказательств.

3. Выполнить пункты объёма работ в указанном порядке, не реализуя соседние задачи.

## Автоматические проверки

Все команды выполняются из корня репозитория. Окружение должно соответствовать согласованным версиям; тесты работают только на временных базах. `scripts/check.sh` создаётся в Task 22, после Task 23 полный запуск включает E2E; `scripts/deploy.sh` и его изолированный `--self-test` создаются в Task 25. Это целевые команды зависимостей, а не существовавшие при аудите файлы.

```bash
git diff --check
bash scripts/check.sh --help
bash scripts/deploy.sh --help
```

Если команда или путь изменены выполненной зависимостью, сначала зафиксировать актуальную замену и причину, затем выполнить её. Ошибка окружения и пропуск обязательной проверки не означают успешную приёмку.

## Ручная проверка

По одному выполнить сценарии чистого запуска и типичного восстановления после неверной конфигурации; проверить ссылки и соответствие --help скриптов.

Ожидаемый результат — критерии приёмки выше. Записать фактическую среду, шаги и наблюдения; ручную проверку не подменять наличием теста.

## Документация и очистка

Корневые документы окончательно сводит Task 27, но изменённые команды уже сейчас записать в результате задачи. Удалить собственные временные файлы/стенды, не чужие правки и не рабочие данные. Зафиксировать доказанные отклонения для ещё не начатых задач.
