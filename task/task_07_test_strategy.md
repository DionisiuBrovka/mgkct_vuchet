## Объём работ

1. Разнести точную арифметику/календарь на unit, схему на Python/PB, HTTP и CAS на server integration, состояние/роутинг на Flutter tests, полный путь на browser E2E.
2. Сохранить смысл действующих тестов прав, CAS, rollback и ввода; заменить тесты миграции старых пользователей на чистую схему, не переносить историческую совместимость.
3. Определить независимые временные базы, динамические порты, управляемые часы, две учительские учётные записи с одинаковым ФИО, завуча и неактивного пользователя; исключить общую изменяемую фикстуру между тестами.
4. Выбрать воспроизводимый способ browser E2E и запуск release-статики; не вводить новый инструментарий без объяснения. Определить, какие тесты добавляют Task 09–21 и какие сквозные проверки добавляет Task 23.
5. Описать итоговый scripts/check.sh, который создаст Task 22, и расширение сквозными тестами в Task 23; все ошибки и пропуски обязательных проверок должны приводить к ненулевому выходу.

```bash

```

Если команда или путь изменены выполненной зависимостью, сначала зафиксировать актуальную замену и причину, затем выполнить её. Ошибка окружения и пропуск обязательной проверки не означают успешную приёмку.

## Ручная проверка

Для CAS и session restore проследить фикстуру, действие, наблюдаемый эффект и cleanup; убедиться в изоляции двух одновременных запусков.

Ожидаемый результат — критерии приёмки выше. Записать фактическую среду, шаги и наблюдения; ручную проверку не подменять наличием теста.
