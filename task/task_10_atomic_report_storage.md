## Цель

Получить минимальную внутреннюю транзакционную операцию новой схемы с CAS и целостностью полного агрегата.

## Ожидаемый результат

Обновлённый superuser-only storage endpoint и тесты конкурентности, ownership детей и полного rollback на новой схеме.

## Объём работ

1. Применить договор внутренней записи Task 05/06: whitelist полей, идентификация периода, expected revision и согласованный результат записи.
2. Атомарно создавать/обновлять заголовок, строки и замены; не дублировать статус в детях. Проверять принадлежность существующих ID и уникальность входных детей.
3. Обеспечить ровно одного победителя при конкурентном первом создании revision=0 и при обновлении существующего отчёта; конфликт возвращать как 409.
4. Сохранять точные десятичные значения без Number-преобразований. Нормализацию пользовательского текста и бизнес-workflow оставить Shelf; структурные и ссылочные инварианты — хранилищу.
5. Добавить mid-write failure после изменения заголовка/первого ребёнка; проверить, что revision, статус, строки и замены вернулись к прежнему состоянию.
6. Доказать, что результат успешной записи относится к её ревизии, и согласовать способ последующего непротиворечивого чтения с Task 12/13.

## Функциональные требования

- Два параллельных write с одной revision дают один успех и один 409, без дублей периода и строк.

Обязательные подробности поведения перечислены в объёме работ. Поля и DTO брать из зафиксированных контрактов.

## Результат выполнения

Реализован [superuser-only storage endpoint](../data/pocketbase/pb_hooks/report_storage.pb.js):
одна `runInTransaction` выполняет CAS заголовка, создание/обновление/удаление
строк и замен. Входная команда и каждый ребёнок имеют whitelist; чужой или
повторённый persistent ID, а также повтор назначения, отклоняются до изменения
агрегата. Десятичные строки передаются PocketBase без Number-преобразования.
Результат содержит ID отчёта и именно записанную ревизию; Task 12/13 должен
читать согласованный агрегат после этого результата, а не собирать его из
кэшированного состояния.

Добавлен изолированный black-box test
[test_report_storage.py](../data/pocketbase/tests/test_report_storage.py). Он
создаёт временную БД и superuser, проверяет отсутствие доступа без superuser,
два одновременных create с `expected_revision=0` (`200` и `409`), ownership,
whitelist, независимое удаление одной из двух замен того же дня и rollback
поздней некорректной decimal после изменения заголовка и детей.

Проверки от 2026-09-17: `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover
-s data/pocketbase/tests -v` — exit 0, 3 tests; `git diff --check` — exit 0.
Ручной QA выполнен тем же отдельным HTTP-стендом: запросы шли в реальный PB
0.40.1 на случайном loopback-порту, наблюдались один победитель CAS и отсутствие
частичных изменений после ошибочной второй замены. Все временные БД и процессы,
созданные тестом, завершаются в `tearDown`; рабочая БД не затрагивается.
