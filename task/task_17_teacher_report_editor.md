## Цель

Дать устойчивую форму шести точных видов часов с предпросмотром итогов, save/submit и режимом чтения.

## Ожидаемый результат

Редактор сырых строк ввода, точный предварительный расчёт, сохранение/отправка, обработка конфликтов и widget/Cubit tests.

## Объём работ

1. Хранить введённый текст отдельно от подтверждённого snapshot, чтобы незавершённая дробь и ошибка валидации не превращались в ноль на blur/rebuild.
2. Применить decimal contract: запятая/точка, пустое=0, значения выше 999, точный вывод без ограничителя десяти знаков; окончательную проверку оставить серверу.
3. Показывать шесть нагрузок с доступными пояснениями, точные предварительные итоги по видам/назначениям/заменам и общий итог; после ответа отображать серверные значения.
4. Save и submit должны посылать один полный aggregate с revision; блокировать повторное действие в ожидании, явно сообщать успех.
5. Сохранять ввод после timeout/422/409; конфликт объяснять и предлагать явное повторное открытие актуального отчёта без auto-merge или молчаливой перезаписи. Замены уже существующего snapshot сохранять без потери до Task 18.
6. Если назначений нет — не показывать форму часов, сообщать обратиться к администратору и оставить путь к заменам. Для submitted/confirmed все изменения отключены; после return редактирование возвращается.

## Что не входит в задачу

CRUD UI замен Task 18, офлайн-синхронизация, автослияние конфликтов, копирование прошлого месяца.

Общие исключения продукта: комментарии/история, экспорт/печать, массовое подтверждение, клиентская админка и офлайн-синхронизация.

## Функциональные требования

- Ввод 1000,125 и длинной дроби сохраняется/отображается точно, итог 0,1+0,2 равен 0,3.
- После сетевой/422/409 ошибки исходные строки и замены остаются видимыми; актуальный snapshot загружается только явным действием.

Обязательные подробности поведения перечислены в объёме работ. Поля и DTO брать из зафиксированных контрактов.
