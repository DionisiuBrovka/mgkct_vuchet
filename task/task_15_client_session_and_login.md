## Цель

Дать пользователю сохраняемый вход и корректный переход в интерфейс роли после серверной проверки.

## Ожидаемый результат

Session lifecycle, состояние восстановления, login/empty/error UI, logout и тесты роутера/сессий.

## Объём работ

1. На старте восстановить согласованную сессию и проверить через Shelf до protected routing; не открывать приватный экран по роли из storage.
2. Публичный список только id/name, выбор по ID, одинаковые ФИО различимы даже при совпавшем коротком суффиксе; русский понятный сценарий без ручного логина.
3. Развести loading, no users, failed directory с retry, неверный пароль и недоступность сервера; запретить повторный login пока запрос идёт.
4. Выполнить logout сервера/локальную очистку согласно контракту и вывести обе роли на login; закрыть deep links другой роли.
5. При 401 и блокировке требовать новый вход, при временной недоступности restore дать retry; отменять запоздалые restore/login после logout и dispose.
6. Добавить тесты перезапуска клиентского состояния, restore обеих ролей, прямой ссылки, expiry/revoke и одинаковых ФИО; хранение пароля недопустимо.

## Что не входит в задачу

Смена/восстановление пароля, экран администрирования, офлайн-режим.

Общие исключения продукта: комментарии/история, экспорт/печать, массовое подтверждение, клиентская админка и офлайн-синхронизация.
