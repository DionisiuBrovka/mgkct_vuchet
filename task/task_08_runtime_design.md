## Объём работ

1. Выбрать конкретные совместимые Flutter/Dart и PocketBase 0.40.1, способ получения PB и проверки версии/контрольной суммы, фиксированные теги или digests образов. Локальный cache сообщает Flutter 3.44.8/Dart 3.12.2, это наблюдение, не уже выбранная версия.
2. Зафиксировать канонические scripts/check.sh и scripts/deploy.sh; deploy должен иметь явно описанные операции первого запуска, повторного запуска/обновления, остановки, статуса и журналов, согласованный --help. Закрепить также `scripts/deploy.sh --self-test`: полностью изолированный smoke первого/повторного deploy с временным проектом/томом, без рабочей .env.
3. Определить поддерживаемый контейнерный движок по реально подготовленной машине: Podman доступен при аудите, Docker не найден. Сохранение двух веток не обязательно; отказ от одной явно документировать и обеспечить понятный preflight.
4. Определить .env.example без секретов, адреса HOST/PORT/POCKETBASE_URL/STATIC_DIR, сервисные credentials, CORS/session-настройки, NO_PROXY, постоянный том и bounded readiness.
5. Задать безопасный явный reset только базы разработки с проверкой пути; повторный deploy новой версии по умолчанию сохраняет её данные. Миграции новой схемы не означают перенос старой базы.
6. Зафиксировать GitHub Actions как исходный технический выбор: локальная конфигурация remote.origin.url указывает на github.com. Проверить доступность runner и допустимую платформу артефактов перед Task 26. Автоматический удалённый CD и адрес сервера не придумывать.

## Что не входит в задачу

Изменения контейнеров, установка на боевую машину, удалённый CD, выдуманные credentials.

Общие исключения продукта: комментарии/история, экспорт/печать, массовое подтверждение, клиентская админка и офлайн-синхронизация.

## Функциональные требования

- Схема даёт доступ к Shelf из LAN и закрывает PB обычным устройствам; хранение сессии согласовано с transport.
- Один и тот же набор версий и команд применим локально, в контейнерах и CI; секреты не передаются Flutter-сборке.

Обязательные подробности поведения перечислены в объёме работ. Поля и DTO брать из зафиксированных контрактов.

## Архитектурные ограничения

- Не добавлять совместимость со старой базой/API и функции вне §20.
