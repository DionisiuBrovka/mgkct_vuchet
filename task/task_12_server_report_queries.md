## Цель

Реализовать новый query API с серверным периодом, правами и точными согласованными итогами.

## Ожидаемый результат

Типизированные query-сервисы/DTO, календарная политика и точная арифметика, ответы teacher periods/admin overview/full report и тесты.

## Объём работ

1. Внедрить управляемые часы и политику Task 03; выдавать преподавателю серверно определённый учебный год и месяцы, запрещать обход согласованных периодов прямым запросом.
2. Читать нормализованные назначения, справочники и строки в согласованный report DTO, включая несохранённый draft revision=0 и отсутствие назначений.
3. Реализовать точную арифметику Task 02: итоги строки, шести видов, назначений, замен и общий итог; не доверять переданным клиентом суммам.
4. Обеспечить согласованное чтение заголовка/детей при конкурентном commit и создании первого отчёта, bounded retry/409 по API, не бесконечный цикл.
5. Реализовать список преподавателей и статусов для admin, согласованный период и фильтрацию по Task 06; сортировать русские имена и различать ID однофамильцев.
6. Применять текущие права к каждому query; учесть согласованные изменения/удаления справочников.

## Что не входит в задачу

Сохранение и переходы Task 13, клиентский интерфейс, аналитическая сводка.

Общие исключения продукта: комментарии/история, экспорт/печать, массовое подтверждение, клиентская админка и офлайн-синхронизация.

## Функциональные требования

- Учитель видит только свои допустимые периоды, завуч — согласованный список всех преподавателей; прямой чужой запрос отклоняется.
- Для 0,1 + 0,2 и длинных дробей все итоги точны; assignment/substitution/grand total не смешаны.

Обязательные подробности поведения перечислены в объёме работ. Поля и DTO брать из зафиксированных контрактов.
