## Цель

Создать общий типизированный клиентский слой нового API с точным хранением чисел и независимостью от PocketBase.

## Ожидаемый результат

Общие модели отчёта/периода/пользователя/ошибок, API DTO mapping, repositories и DI; актуальная кодогенерация и контрактные клиентские тесты.

## Объём работ

1. Перенести общие доменные DTO из teacher в согласованную shared/core-границу, убрать admin → teacher repository-зависимость и неиспользуемые модели после проверки ссылок.
2. Реализовать типизированные DTO по api_contract/api_examples, статус и revision только агрегата, description замены, полные точные итоги и предмет/группу как API-данные.
3. Хранить точные десятичные значения и отдельный сырой ввод, не сводить JSON decimal к double; обеспечить round-trip нормативных примеров.
4. Перестроить ApiService на единые ошибки/таймауты и auth transport Task 04 с интерфейсом для session controller Task 15; не делать retry мутаций автоматически.
5. Обновить DI, Freezed и генерацию; адаптировать существующие экраны минимально для компиляции, не реализуя будущие UX-функции.
6. Протестировать разбор валидных DTO, ошибочного JSON, неизвестного enum и 401/403/409/422 на фикстурах замороженного API. Сервер можно подменить контрактным HTTP mock, поскольку Task 06 и схема уже зафиксированы.

## Что не входит в задачу

Новый экран входа/restore, UX преподавателя/завуча, PB SDK и временная совместимость API.

Общие исключения продукта: комментарии/история, экспорт/печать, массовое подтверждение, клиентская админка и офлайн-синхронизация.

Обязательные подробности поведения перечислены в объёме работ. Поля и DTO брать из зафиксированных контрактов.

## Результат выполнения

Добавлены shared `domain.dart` и typed `ReportRepository`: API DTO хранит все
hours/totals как canonical `DecimalValue` strings, не `double`. `ApiService`
работает с HttpOnly cookie transport, query parameters и error envelope, без
bearer credential. `profileId` удалён из AppUser/login; новый login body —
`{userId,password}`, directory — `{users:[id,name]}`.

Admin Cubit/state/review переведены на shared `ReportDto`/`AdminTeacherDto` и
не импортируют teacher repository/models. Existing teacher UI оставлен только
как временный compile-compatible consumer до задач 16–18; новый shared
repository является единственной границей для новых screens.

Выполнены build_runner generation, `flutter analyze` — exit 0, `flutter test`
— exit 0 (5 tests), `git diff --check` — exit 0. Contract tests проверяют
long decimal, JSON number rejection и typed shared report fixture.
