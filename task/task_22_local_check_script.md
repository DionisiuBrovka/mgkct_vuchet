## Цель

Создать безопасную точку входа, выполняющую весь согласованный набор локальных проверок с понятной сводкой.

## Ожидаемый результат

Создать `scripts/check.sh` и нужные минимальные helpers/isolated smoke harness, контракт --help и инструкция команд в runtime/test документах.

## Объём работ

1. Проверить версии и доступность Flutter/Dart/Python/PB, зависимости и возможность создать собственный temp workspace; не устанавливать инструменты скрытно и не зависеть от глобальных секретов.
2. Выполнять formatter check без изменения, analyze server/client, Python schema tests, Dart tests, Flutter tests, server executable и release Web build; создать server/build перед compile.
3. Запустить необходимый smoke: изолированный PB + собранный Shelf + статический Web, health с доступным/недоступным PB, закрытие внутренних данных; артефакты и порты принадлежат только этому запуску.
4. Сформировать безопасную очистку trap и bounded ожидания, exit !=0 при любой ошибке/отсутствии обязательной стадии, сводку результатов и версий без секретов.
5. Обеспечить запуск из корня и из другого cwd через собственное вычисление пути. Повторный запуск не удаляет пользовательские данные.
6. Подготовить явное подключение browser E2E: Task 23 добавляет сами сценарии и включает их в полный запуск; до Task 23 не утверждать, что E2E реализован. Не создавать переключатель, позволяющий CI молча пропустить обязательные проверки.

## Что не входит в задачу

Мастер-деплой и CI, полная browser E2E-реализация Task 23, изменение бизнес-кода без выявленного дефекта.

Общие исключения продукта: комментарии/история, экспорт/печать, массовое подтверждение, клиентская админка и офлайн-синхронизация.

Обязательные подробности поведения перечислены в объёме работ. Поля и DTO брать из зафиксированных контрактов.

## Автоматические проверки

Все команды выполняются из корня репозитория. Окружение должно соответствовать согласованным версиям; тесты работают только на временных базах. `scripts/check.sh` создаётся в Task 22, после Task 23 полный запуск включает E2E; `scripts/deploy.sh` и его изолированный `--self-test` создаются в Task 25. Это целевые команды зависимостей, а не существовавшие при аудите файлы.

```bash
bash -n scripts/check.sh
bash scripts/check.sh --help
bash scripts/check.sh
git diff --check
```

Если команда или путь изменены выполненной зависимостью, сначала зафиксировать актуальную замену и причину, затем выполнить её. Ошибка окружения и пропуск обязательной проверки не означают успешную приёмку.

## Ручная проверка

Запустить дважды; в изолированной тестовой копии вызвать отсутствующий инструмент и неуспешный health. Проверить exit code, сводку и cleanup.

Ожидаемый результат — критерии приёмки выше. Записать фактическую среду, шаги и наблюдения; ручную проверку не подменять наличием теста.
